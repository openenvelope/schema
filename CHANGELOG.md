## v1.1.0 — 2026-05-16

Proactive agents release. Adds event and condition trigger types, attribution metadata, and forward-compatibility enum value for continuous triggers.

**Added:**

- `schedule.type` enum extended from `["manual", "cron"]` to `["manual", "cron", "event", "condition", "continuous"]`
  - `event` — fires when an inbound webhook arrives. Configure a webhook endpoint in the Envelope workspace; Envelope generates the secret and URL.
  - `condition` — polls at a configured interval and runs the full team only if a lightweight pre-check prompt returns a positive signal. Keeps inference costs manageable for high-frequency monitoring.
  - `continuous` — persistent observation loop for Envelope Local (always-on daemon). Enum value declared for forward compatibility; config fields and implementation are deferred to a future release.
- `schedule.webhookSecret` (string, optional) — HMAC-SHA256 secret for verifying inbound webhook payloads on `event`-triggered teams. Generated by Envelope.
- `schedule.conditionPrompt` (string, optional) — plain-English prompt evaluated on each polling interval for `condition`-triggered teams. The full team runs only if the model returns a positive signal.
- `schedule.conditionInterval` (enum, optional) — polling interval for `condition`-triggered teams. Values: `"15min"`, `"1h"`, `"6h"`, `"24h"`. Defaults to `"1h"`.
- `metadata` (object, optional) — team-level metadata object.
- `metadata.generatedBy` (string, optional) — attribution field. Canonical value: `"Envelope · openenvelope.org"`. Populated automatically by the Envelope export pipeline.

**Fixed:**

- `validate()` — Ajv was initialised without `strict: false`, causing it to throw a runtime exception on any team definition that includes an `icon` field (which has `format: "uri"` in the schema). The validator now correctly ignores unknown format annotations rather than throwing. All other validation behaviour is unchanged.

**Compatibility:**

All changes are additive. Existing `.envelope.json` files with `schedule.type: "manual"` or `schedule.type: "cron"` are fully valid against v1.1.0. No existing field has been changed or removed. Parsers that do not recognise the new fields ignore them.

## v1.0.0 — 2026-04-28

Initial public release.

**Schema:** `https://schema.openenvelope.org/team/v1.json`

**Added:**

- Top-level team fields: `$schema`, `name`, `slug`, `version`, `description`, `visibility`, `agents` (required); `category`, `tags`, `pricing`, `forkable`, `forkedFrom`, `timeout`, `readme`, `icon`, `inputs`, `outputs`, `requiredSecrets`, `requiredVariables`, `changelog` (optional)
- `agents` array with full `AgentDefinition`: `key`, `name`, `title`, `role` (required); `adapterType`, `reportsToKey`, `capabilities`, `prompt`, `model`, `modelConfig`, `allowedHosts`, `accessPolicy`, `metadata` (optional)
- `ModelConfig` object: `provider`, `model` (required); `temperature`, `maxTokens`, `timeoutMs` (optional)
- `AccessPolicy` object with ordered `rules` array: per-rule `host`, `methods`, `pathPrefix`, `action`, `reason`; `action` values: `allow`, `deny`, `require_approval` (forward-compatible, treated as `deny` in v1)
- `gates` array with `HumanGate`: `name`, `type`, `afterStep`, `triggersStep`, `fields`, `trigger`, `onReject` (required); `thresholdCount`, `recordActions`, `timeout` (optional)
- `pipeline` array with `PipelineStep`: `key`, `agentKey` (required); `label`, `dependsOn` (optional)
- `Pricing` with `model` values: `free`, `per_run`, `per_k_tokens`, `subscription` (subscription planned — not yet available)
- `ForkedFrom` attribution object for forked teams
- `TeamTimeout` with `runMs` and `agentMs`
- Category enum: 15 values (`customer-support`, `sales`, `marketing`, `finance`, `hr`, `devops`, `engineering`, `data-analysis`, `legal`, `research`, `content`, `product`, `security`, `operations`, `other`)
- Adapter enum: `http`, `claude_local`, `codex_local`, `gemini_local`, `opencode_local`, `cursor_local`
